# ドキュメントおよびコミュニケーションガイドライン

本ドキュメントは、AIエージェントがテキストやドキュメントを生成する際の文体、表現、および文章構造に関するルールを定義する。

## 1. コミュニケーションおよび文体（AI臭さの排除）

AI特有の冗長な表現を排除し、客観的かつ簡潔な技術文書スタイルを徹底する。

- **文体とトーン**: 原則として「である・だ」調（またはプロジェクトで統一された「です・ます」調）を使用し、客観的な事実と論理に基づく記述とする。
- **無駄の排除**: 「～について説明します」「結論から言うと～」といった冗長な前置きやまとめは記述しない。
- **対等な関係性**: 過剰な同意（「おっしゃる通りです」等）や謝罪を廃し、対等なエンジニアとしてのプロフェッショナルな対話を重視する。機械翻訳のような不自然な直訳表現も避ける。
- **表現の多様性**: 特定の文末表現（「～となります」「～を行います」など）の連続を避け、自然な日本語を構成する。

## 2. ドキュメント構造（抽象から具体への展開）

出力する文章は、全体像（抽象）から実装詳細（具体）へと段階的にブレイクダウンするトップダウンアプローチを徹底する。

- **標準セクション構成**: タスクの性質に応じつつも、原則として以下の技術文書フォーマットに準拠する。
  1. 【背景/目的】
  2. 【要件/仕様】
  3. 【設計/実装】
  4. 【テスト/確認事項】
- **視覚化の推奨**: 複雑な処理フロー、システムアーキテクチャ、状態遷移などを説明する際は、積極的に Mermaid を用いて図解し、読者の認知負荷を下げる。
