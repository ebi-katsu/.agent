# ユーザー開発環境・基本構成ルール (ENV.md)

本ドキュメントは、ユーザーのローカルPC環境における標準的なディレクトリ配置、利用ツール、およびOS設定のデフォルト（推奨設定）を定義する。

## 優先順位の原則

AIエージェントが作業を行う際、設定の優先順位は以下の通りとする。

1. **リポジトリ固有の設定（最優先）**: 作業対象のリポジトリ内に存在する設定ファイル（`package.json`, `docker-compose.yml`, 各リポジトリ配下のローカルルール等）を常に優先する。
2. **本ドキュメント（グローバル設定）**: リポジトリに指定がない場合のフォールバック（デフォルト）として機能する。

また、本ドキュメントはあくまで「推奨」であり、タスクの性質上より最適な手法・ツールが存在する場合は、本ドキュメントに縛られず柔軟に代替案を選択・提案してよい。

## 1. ディレクトリ配置ルール

- **メインワークスペース**: 全OSにおいて、ホームディレクトリ配下の `~/develop/repository/` を開発プロジェクトの標準的なクローン・作業ディレクトリとする。
- **一時検証用（プレイグラウンド）**: 少しだけ試したいコードや一時的な検証プロジェクトは、`~/develop/playground/` （または `sandbox`）のような専用ディレクトリにまとめる。
- **自作スクリプトと設定の配置**:
  - 設定関連は [XDG Base Directory Specification](https://specifications.freedesktop.org/basedir-spec/basedir-spec-latest.html) に準拠する。
  - ユーザー自作のスクリプトは、設定ファイルと共にシェルごとの設定ディレクトリに配置する（PowerShellの場合は `~/.config/powershell`、Zshの場合は `~/.config/zsh`）。
  - 複数の環境（Windows, WSL2, ネイティブUbuntu）を跨ぐこれら設定ファイル（dotfiles等）は、Gitリポジトリで一元管理し、各環境へクローンして展開する。

## 2. 標準グローバルツールとワークフロー

- **OS環境**: 開発のベースOSとして Windows、WSL2上のUbuntu、およびネイティブな独立したUbuntu環境を併用する。
- **Gitの改行コード**: 全環境で `LF` に統一する。Windows環境でも `core.autocrlf = false` とし、エディタ設定等でLFを強制する。
- **コンテナ技術**: 開発環境には原則として Docker または Dev Container を採用し、複数OS間での環境のポータビリティと分離を確保する。
- **パッケージ管理**:
  - Windows環境: アプリケーション管理の標準として `winget` を採用する。
  - Ubuntu環境: パッケージ管理の標準として `apt` (および必要に応じて公式の `snap`) を採用する。
  - Node.js関連: ホストOSにおける Node.js 関連のパッケージ管理には `pnpm` を採用する。

## 3. OS・シェル環境の設定

- **Windows環境**: 標準シェルとして PowerShell (`pwsh`) を採用する。
- **Ubuntu環境**: 標準シェルとして `zsh` を採用する。
