# AIエージェント向け Skill作成・配置ガイドライン

本ドキュメントは、AIエージェントが本プロジェクトにおいて新しいSkillを `~/.agent/skills/` 配下に作成・配置する際の標準ルールおよび制約事項を定義する。
エージェントはSkillを自律的または指示に基づいて作成する場合、必ず本ガイドラインに準拠すること。

## 1. 命名規則と基本設定

*   **ディレクトリ・Skill名のフォーマット**:
    Skillのディレクトリ名、および `SKILL.md` のフロントマターに記述する `name` プロパティは、すべて**ケバブケース（小文字・ハイフン区切り）**で統一する。
    *   正: `deploy-frontend-app`
    *   誤: `DeployFrontendApp`, `deploy_frontend_app`
*   **接頭辞**:
    Skillの名前の接頭辞にセクション名を付与する
    *   例: `git-generate-commmit`, `review-code`
*   **使用言語**:
    フロントマター（メタデータ）およびMarkdown本文の手順は、チームメンバーの直感的な読み書きと保守性の観点から、原則として**日本語**で記述する。

## 2. フロントマター（メタデータ）の定義

`SKILL.md` の先頭には必ずYAMLフロントマターを配置し、以下のルールに従って記述する。

*   **`description` の明確化（必須要件）**:
    エージェントが「いつ、どのようなタスクでこのSkillを呼び出すべきか」を正確に判断できるよう、発動条件を三人称視点で具体的に記述する。
    *   記述例: 「ユーザーからフロントエンドアプリケーションのステージング環境へのデプロイを求められた場合に使用する。」

## 3. ファイル構造とプログレッシブ・ディスクロージャー

LLMのコンテキストウィンドウ（読み込み上限）を節約するため、情報の一極集中を避け、ファイル分割（プログレッシブ・ディスクロージャー）を推奨する。

*   **`SKILL.md`**:
    簡潔な作業手順やフローの記述に留める。
*   **`scripts/`**:
    複雑なシェルコマンドや自動化スクリプトは、このディレクトリ配下に別ファイルとして切り出し、`SKILL.md` から相対パスで参照する。
*   **`references/`**:
    詳細な背景知識、APIリファレンス、長大な設定例などはこのディレクトリ配下に分離する。

## 4. 検証手順の組み込み

*   **実行結果の検証（推奨）**:
    エージェントが手順を確実に行い、サイレントエラーを防ぐため、可能な限り各ステップや手順の最後に「実行結果の検証方法」を記述する。
    *   例: ログファイルの確認コマンド、`--dry-run` による事前確認、ステータスチェックのAPI呼び出しなど。

## 5. Skill作成時の合意形成プロセス

エージェントがタスク遂行の過程で新しいSkillの必要性を認識し、自発的に作成・提案する場合のプロセスを以下に定める。

*   **事前合意の必須化**:
    エージェントは独断でSkillファイルを生成してはならない。事前に「作成目的」「想定されるディレクトリ構成案」「発動条件（description）」をユーザーに提示し、明示的な承認を得てから生成処理を実行する。

## 6. カスタムスキル一覧

以下は今後作成予定の、ユーザー固有のタスクを自動化・効率化するためのスキル構想リストである。用途別に分類している。

### git - Git関連

- **git-workflow-assistant**: プロジェクトのGitブランチ戦略に沿った操作手順をガイドする。
- **git-commit-generator**: 変更内容を解析し、プロジェクトの規約に沿ったコミットメッセージを自動生成する。

### docker - Docker関連

- **docker-setup-helper**: 開発環境用の `Dockerfile` や `docker-compose.yml` を要件に応じて生成・最適化する。
- **docker-troubleshooter**: コンテナ起動時のエラーログ解析やネットワーク周りのトラブルシューティングをサポートする。

### design - 設計書関連

- **basic-design-generator**: プロジェクトのボイラープレートやコーディングルールを参照し、要件から基本設計書のひな形を作成する。
- **api-spec-designer**: 要件に基づき、APIのインターフェース設計や仕様書のドラフトを生成する。

### coding - コーディング関連

※ ボイラープレートとルールを参照して、フレームワーク固有のコードを生成する。

- **spring-boot-scaffolder**: Spring Bootのルールに基づき、Controller, Service, Repository層のコードを生成する。
- **react-component-generator**: Reactのルールに基づき、要件に合わせたコンポーネント（およびテストの雛形）を生成する。
- **nestjs-module-generator**: NestJSのアーキテクチャに準拠したモジュール、コントローラー、サービスのコードを生成する。

### review - レビュー

- **code-reviewer**: プロジェクトのルールやベストプラクティスに基づき、実装コードをレビューして修正案を提示する。
- **design-reviewer**: 作成された設計書に対し、要件の漏れや矛盾、非機能要件の考慮不足がないかレビューを行う。

### test - テスト

- **unit-test-generator**: 実装されたコードに対し、カバレッジや異常系を意識したユニットテストコードを自動生成する。
- **test-scenario-planner**: 要件定義や設計書をもとに、結合テストやE2Eテストのシナリオ・テストケースを設計する。

### idea - ブレインストーミング

- **architecture-brainstormer**: 新規開発時の技術選定やアーキテクチャ設計について、複数の選択肢とトレードオフを提示し壁打ち相手となる。
- **ideation-partner**: 課題解決のためのゼロベースのアイデア出しを行い、多角的な視点から解決策を複数提案する。

### skill - スキル評価

- **skill-create**: いつくかの質問を基にスキルを作成する
- **skill-eval**: スキルの内容が妥当かどうかを評価する。(AIで実行できるタスク難度か、Python等のスクリプト等で機械的に実行する方が妥当ではないか等)
